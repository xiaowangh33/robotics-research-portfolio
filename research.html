TIMING IS PART OF THE PLANT

Short-horizon state prediction and calibrated confidence under delay, jitter, and missed cycles.

A proposed study of how an RL or MPC locomotion controller should update its belief—and its risk tolerance—when sensing, actuation, and computation no longer arrive on the nominal schedule.

HYPOTHESIS

Timing faults should be estimated as structured state uncertainty, not absorbed as anonymous noise.

Legged and wheel-legged controllers often assume that observation xt and action ut refer to the same current instant. Real systems violate this assumption: packets wait, sensors update asynchronously, computation time varies, and low-level loops may miss a cycle.

I propose to infer a short-horizon predictive distribution over the effective current state using recent state estimates, issued commands, action history, timestamps, age-of-information, and missed-cycle counters. The controller would receive both a state estimate and calibrated confidence.

The central test is whether this confidence signal improves graceful degradation: preserving useful motion when uncertainty is modest, while changing gait, speed, action magnitude, or planning risk when the estimate becomes unreliable.

FAILURE TAXONOMY

Four timing failures that change the effective closed loop.

01

Observation delay

The controller acts on a state that was valid in the past; contact mode or body velocity may already have changed.

02

Action delay

The plant receives a command later than the policy assumes, changing phase and effective feedback gain.

03

Jitter

Variable inference, transport, and actuator timing prevents a fixed-delay compensator from matching every cycle.

04

Missed cycles

A held or skipped command changes the action history and may push the robot across a contact or stability boundary.

PROPOSED METHOD

Predict, calibrate, then let confidence influence control.

This is a research plan, not an implemented system. The blocks define the intended experiment and the interfaces that would need to be validated.

INPUT / 01

Timestamped history

Recent states, commands, action history, age-of-information, cycle duration, and missed-update indicators.

ESTIMATE / 02

Short-horizon distribution

Predict the effective current or near-future state together with epistemic and/or aleatoric uncertainty.

CALIBRATE / 03

Reliable confidence

Test whether predicted intervals match observed error under both in-distribution and shifted timing conditions.

CONTROL / 04

RL or risk-aware MPC

Use state and confidence as policy context or within chance/risk constraints, while respecting compute deadlines.

EVALUATION PLAN

Test recovery, worst cases, calibration, and added latency.

Average tracking alone is not enough. A timing-aware controller should be evaluated on whether it recognizes when its belief is weak and whether that recognition changes physical outcomes.

PLATFORMS

Begin in simulation, then validate on a wheel-legged or quadruped platform with instrumented policy, transport, and actuator timing.

PERTURBATIONS

Controlled observation delay, action delay, variable jitter, bursty missed cycles, and combinations with mass/friction/actuator mismatch.

BASELINES

Domain-randomized PPO, recurrent policy, deterministic state predictor, fixed-delay compensation, and an MPC/RL controller without confidence input.

PHYSICAL METRICS

Fall or task success, tracking error, recovery time, intervention threshold, worst-case outcome, and degradation as timing faults grow.

ESTIMATION METRICS

Prediction error, interval coverage, calibration error, out-of-distribution detection, compute time, and additional closed-loop latency.

ABLATIONS

Remove timestamps, action history, missed-cycle counters, or confidence-conditioned control to identify which components matter.

DESIGN CONSTRAINTS

The estimator cannot solve timing failure by creating more timing failure.

REAL-TIME BUDGET

Bound worst-case compute.

Report not only average estimator runtime but its tail latency and how it interacts with policy/MPC deadlines.

TIMESTAMP SEMANTICS

Define when every signal was valid.

Sensor acquisition, estimator output, command issue, bus transmission, and actuator application should not share an ambiguous timestamp.

CALIBRATION

Confidence must predict error.

A numerical variance is only useful if it is calibrated under both nominal data and timing shifts not seen during training.

GRACEFUL DEGRADATION

Uncertainty must change action.

The system should expose a decision rule: continue, reduce speed, switch behavior, replan, or stop as uncertainty increases.
